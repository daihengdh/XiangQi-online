NNUE：象棋引擎里的"带权重"算法pikafish.nnue · 50MB

你桌面上那个 960×750 的棋盘程序、以及你网页项目里即将接入的皮卡鱼（Pikafish），强就强在这个文件 —— 本文讲清它到底是什么、怎么一步步算出一步棋。

1一句话：它是什么

NNUE（Efficiently Updatable Neural Network，可高效增量更新的神经网络）是替代"人工规则评估函数"的神经网络评估器。注意它不是 AlphaGo 那种"网络直接选步"的模型 —— 它只做一件事：拿到一个局面，输出一个分数（谁好、好多少）。真正"思考"走哪步的，仍然是经典的 alpha-beta 搜索树。

搜索树negamax + α-β剪枝
置换表 + 静态搜索
⇄
NNUE 评估叶子节点局面
→ 一整个过程
→
一个分数如 +137
（红方优 1.37 兵）

渊源：2018 年日本将棋程序YaneuraOu 首创（作者中西貴裕/Yu Nasu），2020 年 Stockfish 引入后统治国际象棋；皮卡鱼（Pikafish）把 Stockfish 框架移植到象棋规则上，配合为象棋重做的网络与训练数据，成为公认最强开源象棋引擎。

每个箭头就是代码里的一层。整个网络是前馈全连接结构，没有任何"看棋盘图像"的卷积 —— 它吃的是结构化特征，速度因此极快（微秒级）。

3特征怎么编：一个棋子 = 一个索引

象棋一共 7 种棋子 × 2 色 = 14 种，棋盘 90 格。NNUE 的核心编码思想是"棋子 + 位置 + 本方将的位置"三元组合：

// 伪代码：红方视角下，"黑马在(3,6)格、我的将在(9,4)格" → 一个特征编号
featureIndex = (pieceType, pieceColor, pieceSq, kingSq)   // HalfKAv2 式因子化

同样的棋盘会生成两套视角（走子方视角 / 对手视角，相当于把棋盘镜像翻转），两套各自算一份 2560 维向量再拼接 —— 这样网络天然理解"轮到谁走、谁在进攻"。

为什么要把"将的位置"编进特征？因为所有子力的价值都相对王的位置而定：同样的车，在将军方向上是攻子，在底线可能是守子。这个设计让 22528 维的"理论特征空间"虽大，却可以因子化为少量基础嵌入之和 —— 这也是 50MB 能装下网络的关键（见第 5 节）。

4"高效可更新"：名字里的精髓（试一试 ↓）

搜索树每走一步棋，如果每次都把 90 个格子全部重新算一遍网络，就太慢了。NNUE 的杀招：每个激活特征对应一个 2560 维的权重向量，网络第一层的输出 = 所有激活特征向量的总和。于是走一步棋只需：

// 车从 A 格走到 B 格：只改 2 个特征
accumulator -= W["车在A格"]   // 减去离开的
accumulator += W["车在B格"]   // 加上到达的
//吃子再减去被吃子的向量。O(1) 增量更新，配合 SIMD 一次加减 8~16 个分量

5pikafish.nnue 这 50MB 里装的是什么

就是训练好的量化权重。网络先在 float32 下训练，再量化成整数存储以提速：

部分内容存储方式
特征变换层"特征索引 → 2560 维向量"的查询表（主体）INT16 量化
隐藏层 ×2~32560 → 更窄层 → 更窄层 → 1 的连接权重与偏置INT8 量化
元信息版本号、特征集名、桶划分、Hash 校验文件头

理论组合特征有 22528 个，但每个组合的向量可以由基础嵌入相加得到（因子化），所以实际存储远小于 22528×2560；运行时引擎用 AVX2 / AVX-512 / NEON 指令一次加减 8~16 个整数分量，这就是"微秒级出分"的工程基础。

这些权重怎么来的：先用引擎自我对弈产生数亿个局面（Pikafish 官方数据来自 Pika Xiangqi Zero 团队），再用"最终对局结果 + 更强引擎的搜索评分"做监督目标训练网络，随后多轮"训练 → 对打 → 微调"。权重本身没有任何人类棋谱规则 —— 象棋知识全部隐含在那 2500 万个数字里。

6和搜索的关系：只换了"眼睛"，没换"大脑"

皮卡鱼的搜索框架和你项目里那个手写引擎同源同构（都是 Stockfish 一脉的套路）：迭代加深、negamax、α-β 剪枝、置换表、杀手着法启发、静态搜索（quiescence）、空着裁剪。差别只有两点：

① 评估器
内置引擎：人工规则（子力表 + 若干位置分，几十行代码）
皮卡鱼：NNUE（2500 万个训练出来的参数）

② 工程深度
多线程（LazySMP）、更精细的剪枝与时间管理、数十年 Stockfish 社区的打磨

这就是为什么基准里 4:0 全被将死：搜索思路一样，"看局面的眼睛"差了几个数量级。NNUE 评估准 → 剪枝又快又狠 → 同样 1 秒能搜深得多（实测初始局面 800ms 搜到深度 27，内置引擎同期约 6~8 层）。

7在你的项目里怎么用它（UCI 会话实录）

引擎是个独立进程，走标准 UCI 协议（文本行命令）。下面是本机实测记录（tools/pikafish-uci.js 可复现）：

> uci
< id name Pikafish ...          // 引擎自报家门
< uciok
> setoption name EvalFile value pikafish.nnue   // 指定权重文件 ← 50MB 在这里生效
> isready
< readyok
> position startpos
> go movetime 800
< info depth 27 score cp 27 ...                // 搜索过程：深度/评分
< bestmove g3g4 ponder e6e5                    // 最终着法（兵三进一）

接入方式 = 服务器用子进程启动 pikafish.exe，网页每步把局面 FEN 发给服务器、服务器转发给引擎、拿 bestmove 回来。NNUE 权重由引擎自己加载，调用方完全不用懂神经网络。

8常见疑问

问题回答
它联网吗？会自己学习吗？不联网、不对局中学习。权重是死文件，训练在离线集群完成；引擎只做"读权重 + 推理"。
权重能自己换吗？能。同一架构下换 .nnue 文件即换"棋风/棋力"，UCI 选项 EvalFile 指定路径。
为什么不用 GPU？NNUE 是小而密的全连接网络，CPU 的 SIMD 指令吞吐足够，单机多核即可实时运行，省去 GPU 依赖 —— 这正是它优于大模型方案的地方。
为什么不直接用大模型选步？搜索树每秒要评估几十万~上百万个局面，大模型单次推理延迟太高；NNUE 单次评估微秒级，是唯一能塞进搜索循环的档位。
那 50MB 文件删掉会怎样？引擎直接报错退出 —— 没有权重它没有评估能力。
